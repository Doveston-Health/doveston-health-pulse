PUL-008 AUTOMATED QUALITY FOUNDATION
====================================

Required branch
---------------
feature/pul-008-automated-quality-foundation

Package purpose
---------------
This ZIP contains only files added or changed for PUL-008. It adds ESLint,
automated contract tests, non-destructive Prisma migration validation,
Gitleaks credential scanning, GitHub Actions CI and quality documentation.

Installation on Windows 11
--------------------------
1. Confirm the repository is on the required branch:

   git branch --show-current

2. Commit or back up any existing local work.
3. Extract this ZIP.
4. Copy its contents into the root of the doveston-health-pulse repository.
   Preserve the included folders and allow the listed files to replace the
   existing versions.
5. Do not copy a .env file, database data or node_modules from elsewhere.
6. Install the exact dependency tree:

   npm.cmd install

   After package-lock.json has been accepted, npm.cmd ci may be used for a
   clean, lockfile-driven installation.

Do not change, bypass or relax PowerShell execution policy. Use npm.cmd
instead of npm and npx.cmd instead of npx on Windows.

Verification on Windows
-----------------------
Run these commands one at a time:

   npm.cmd run lint
   npm.cmd test
   npm.cmd run quality
   npm.cmd run db:generate
   npm.cmd run db:migrate:check

The migration-status command uses the DATABASE_URL in the local environment.
It is non-destructive. Do not run db:reset for PUL-008 verification.

For local application verification, start the normal development service:

   npm.cmd run dev

Then manually confirm:

* login works;
* the Director dashboard loads;
* logout works;
* unauthenticated protected access remains blocked;
* /api/health works;
* /api/ready works; and
* /healthz works.

Do not use production-mode startup for local authentication testing.

GitHub verification
-------------------
After the branch is pushed and a Pull Request is opened, GitHub Actions runs
the workflow in .github\workflows\quality.yml. The stable check name is:

   PUL-008 quality workflow

The workflow installs with npm ci, lints, tests, generates Prisma Client,
deploys migrations to an isolated PostgreSQL 16 database, validates migration
status and scans repository history with Gitleaks.

A repository administrator must configure branch protection for main to
require "PUL-008 quality workflow" before merge. The workflow cannot enable
that repository setting. Do not claim it is enabled until GitHub shows the
rule and a successful workflow run.

Small testability changes
-------------------------
The authentication router, system router and readiness controller now expose
dependency-injected factory functions. Their existing production exports use
the same original handlers and middleware, so runtime routes and contracts do
not change. Tests use the factories with in-memory sessions and stubbed health
and authentication dependencies; they do not use the clinic database.

Dependencies
------------
Development dependency added:

* eslint
* globals (ESLint environment definitions)

No production runtime dependency is added. Node's built-in test runner and
HTTP client are used; no large testing framework is introduced.

Safety
------
The package contains no real credentials, .env file, patient information,
database data or generated runtime secret. It does not change authentication
rules, database models, migrations, public response contracts or application
features.
