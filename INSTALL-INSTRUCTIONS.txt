PUL-009 CLINIKO READ-ONLY INTEGRATION AND INITIAL SYNC
======================================================

Required branch
---------------
feature/pul-009-cliniko-read-only-integration

Installation
------------
1. Confirm and review the branch before extracting:

   git branch --show-current
   git status --short
   git diff --stat

2. Commit or back up unrelated local work.
3. Extract the ZIP into the repository root, preserving folders and replacing
   only the files listed in the manifest below.
4. Install dependencies:

   npm.cmd install

5. Start local PostgreSQL and confirm it is healthy:

   docker compose up -d postgres
   docker compose ps

6. Create a development migration from the supplied schema only if reviewing
   the migration interactively; otherwise apply the committed migration:

   npm.cmd run db:migrate:deploy

7. Generate Prisma Client and seed the baseline integration records:

   npm.cmd run db:generate
   npm.cmd run db:seed

Local Cliniko configuration
---------------------------
Edit .env in an editor. Do not echo or print the real API key in terminal
output, shell history, screenshots, logs or support messages.

Use:

CLINIKO_ENABLED=true
CLINIKO_BASE_URL=https://api.au4.cliniko.com/v1
CLINIKO_API_KEY=replace-with-real-cliniko-api-key
CLINIKO_USER_AGENT=Doveston Health Pulse (support@example.com)

Replace the key placeholder locally and use a genuine monitored contact email
in the User-Agent. Never commit .env.

Automated verification
----------------------
Run each Windows PowerShell command separately:

   npm.cmd run lint
   npm.cmd test
   npm.cmd run quality
   npm.cmd run db:generate
   npm.cmd run db:migrate:check

Do not change or bypass PowerShell execution policy. Use npm.cmd instead of
npm and npx.cmd instead of npx.

Manual verification
-------------------
1. Start Pulse in development mode:

   npm.cmd run dev

2. Sign in as a Director or Practice Manager.
3. Open Settings and confirm the Cliniko panel states:

   Cliniko remains the source of truth. Pulse performs read-only synchronisation.

4. Confirm configured state, counts and recent jobs load.
5. Select Test connection. Confirm only the stable Pulse success or failure
   message appears and the API key is never displayed.
6. Select Sync now once. Confirm the running state prevents a second sync.
7. Confirm a successful job shows aggregate counts only.
8. Confirm ADMIN and CLINICIAN receive HTTP 403 for Cliniko management routes.
9. Confirm an unauthenticated API request receives HTTP 401.
10. Confirm health, readiness, login, dashboard and logout still work.

Database count inspection
-------------------------
Open Prisma Studio without displaying patient rows in screenshots:

   npm.cmd run db:studio

Confirm aggregate table counts for:

* cliniko_businesses
* cliniko_practitioners
* cliniko_patients
* cliniko_bookings
* cliniko_booking_patients

Do not copy patient rows or contact information into logs, issues or reviews.

Final review
------------
After testing:

   git diff --check
   git diff --stat
   git status --short

Confirm .env, node_modules, database volumes and generated secrets are absent
from Git status.

Security boundaries
-------------------
The implementation performs Cliniko GET requests only. It does not persist API
keys, clinical notes, booking notes, raw responses or excluded patient fields.
It does not implement Xero, expose patient rows, add unauthenticated routes or
weaken authentication.
